# Каталог настольных игр

## Назначение
Приложение предназначено для ведения каталога настольных игр: хранения информации об играх, их категориях, а также отзывов пользователей с числовой оценкой от 0 до 10.

Консольная версия приложения (ПР3) дополнена веб-интерфейсом на Django (ПР5),
который в ПР6 переведён на систему шаблонов Django (Django Template Language).

Приложение позволяет:
- просматривать список игр в браузере;
- просматривать карточку конкретной игры: категорию, год выпуска, средний рейтинг и отзывы;
- просматривать список отзывов в браузере;
- просматривать конкретный отзыв со ссылкой на игру;
- искать и сортировать игры (консольная версия);
- добавлять отзыв с оценкой от 0 до 10 (консольная версия);
- хранить данные между запусками приложения в JSON.

## Используемые технологии
- Python 3;
- Django 5.2 — веб-фреймворк;
- Django Template Language (DTL) — шаблоны страниц;
- HTML5 — разметка веб-страниц;
- CSS3 — собственные стили проекта (static-файлы);
- JavaScript — небольшое клиентское поведение интерфейса;
- Bootstrap 5.3 (через CDN) — базовая вёрстка;
- JSON — хранение данных;
- pytest — автоматизированные тесты;
- flake8 — проверка качества кода.

## Целевая аудитория
Любители настольных игр, которые хотят вести учёт игр в своей коллекции, оставлять оценки и отзывы, а также находить игры по категориям перед покупкой или игровым вечером.

## Предметная область
Предметная область — каталогизация настольных игр и пользовательских отзывов. Каждая игра относится к одной категории и может получать отзывы с числовыми оценками от пользователей.

## Основные сущности (классы ПР3, пакет `models/`)

### Category — категория
Атрибуты: `id`, `name`, `description`. Метод `__str__()`.

### Game — игра
Атрибуты: `id`, `title`, `category` (объект `Category`), `release_year`.
Методы: `average_rating()` — средняя оценка по отзывам, `rating_label()` — текстовая метка качества,
`card()` — текстовая карточка для консоли, `__str__()`.

### User — пользователь
Атрибуты: `id`, `name`. Метод `__str__()`.

### Review — отзыв (связующая сущность)
Атрибуты: `id`, `game` (объект `Game`), `user` (объект `User`), `score` (0–10), `comment`. Метод `__str__()`.

## Страницы веб-интерфейса

| URL | Страница | View-функция |
|---|---|---|
| `/` | главная: описание каталога, статистика и навигация | `homepage.views.index()` |
| `/games/` | список игр из `data/games.json` со средним рейтингом | `catalog.views.games()` |
| `/games/<int:game_id>/` | карточка игры и её отзывы | `catalog.views.game_detail()` |
| `/reviews/` | список отзывов из `data/ratings.json` | `ratings.views.reviews()` |
| `/reviews/<int:review_id>/` | отзыв: игра, пользователь, оценка, комментарий | `ratings.views.review_detail()` |
| любой другой адрес | собственная страница 404 | `homepage.views.page_not_found()` |

Если игра или отзыв с указанным идентификатором не найдены, шаблон страницы выводит сообщение
(ветка `{% else %}`), а `render()` возвращает код статуса 404.
Собственная страница 404 (`homepage/404.html`) подключена через `handler404` в `boardgames/urls.py`
и видна при `DEBUG = False`.

Генерация HTML непосредственно в Python-коде веб-представлений не используется: функция `page()`
из ПР5 удалена. Представления только загружают данные, готовят словарь контекста и вызывают
`render(request, "<шаблон>", context)`.

## Django Template Language (ПР6)

### Базовый шаблон и наследование
Общий шаблон `templates/base.html` содержит объявление документа, `<head>`, подключение Bootstrap,
собственного CSS и JavaScript, навигацию, основной контейнер и подвал. Дочерние шаблоны начинаются
с `{% extends "base.html" %}` и переопределяют блоки `{% block title %}` и `{% block content %}`.

### Включаемые шаблоны
| Шаблон | Назначение | Где подключается |
|---|---|---|
| `templates/includes/navigation.html` | навигация с логотипом | `base.html` |
| `templates/includes/score_badge.html` | бейдж оценки, цвет выбирается через `{% if %}/{% elif %}` | карточка игры, отзывы |
| `catalog/includes/game_card.html` | карточка одной игры | `game_list.html` |
| `ratings/includes/review_item.html` | строка одного отзыва | `review_list.html`, `game_detail.html` |

Данные во включаемый шаблон передаются из внешнего цикла или через `with`:
`{% include "includes/score_badge.html" with score=review.score %}`.

### Контекст, циклы и условия
Представления передают данные через словарь контекста, например `{"reviews": reviews_list}`.
Списки выводятся циклом `{% for ... %}`, пустые коллекции обрабатываются `{% empty %}`.
Условия `{% if %}` используются для страниц «не найдено», цвета оценки и пустых значений.
Расчёты (средняя оценка, текстовая метка рейтинга, сортировка) остаются в Python-коде.

### Фильтры шаблонов
- `{{ game_rows|length }}`, `{{ reviews|length }}` — количество элементов;
- `{{ game.title|default:"Без названия" }}` — значение по умолчанию;
- `{{ review.comment|truncatechars:40 }}` — сокращение комментария в списке;
- `{{ score|floatformat:"-1" }}` — вывод оценки (8,5 или 9);
- `{{ category.description|lower }}` — описание категории на главной.

### Именованные URL и пространства имён
| Пространство имён | Маршрут | Адрес |
|---|---|---|
| `homepage` | `homepage:index` | `/` |
| `catalog` | `catalog:list`, `catalog:detail` | `/games/`, `/games/<int:game_id>/` |
| `ratings` | `ratings:list`, `ratings:detail` | `/reviews/`, `/reviews/<int:review_id>/` |

Ссылки в шаблонах формируются тегом `{% url %}`, например `{% url 'catalog:detail' game.id %}`,
жёстко заданные адреса не используются.

### Статические файлы
Каталог `homepage/static/homepage/`: `css/style.css` (собственные стили карточек, бейджей,
навигации и подвала), `js/main.js` (текущий год в подвале и подсветка активного пункта меню),
`img/logo.png` (логотип-кубик). В `base.html` используются `{% load static %}` и
`{% static 'homepage/css/style.css' %}`. Проверка: `python manage.py findstatic homepage/img/logo.png`.

## Основные операции

### Используется в веб-интерфейсе (ПР5–ПР6)
- `load_catalog()` — загрузка категорий, игр, пользователей и отзывов из JSON;
- `sort_games()` — сортировка игр по названию на странице списка;
- `find_game_by_id()` — поиск игры по ID (добавлена в ПР5);
- `find_review_by_id()` — поиск отзыва по ID (добавлена в ПР5);
- `reviews_for_game()` — отзывы конкретной игры;
- `Game.average_rating()` и `Game.rating_label()` — рейтинг игры.

### Отложено до следующих работ
Эти операции реализованы в ПР2–ПР3 и работают в консольной версии. В веб-интерфейсе они появятся, когда будут добавлены формы и POST-запросы:
- поиск игры по названию (`find_games()`);
- фильтрация игр по категории (`filter_games_by_category()`);
- добавление игры, категории, пользователя (`add_game()`, `add_category()`, `add_user()`);
- создание отзыва (`create_review()`);
- сохранение данных (`save_catalog()`).

## Хранение данных
Данные хранятся в JSON-файлах `data/categories.json`, `data/games.json`, `data/users.json`, `data/ratings.json`.
При загрузке они преобразуются в объекты `Category`, `Game`, `User`, `Review`; связи в JSON хранятся как
`category_id`, `game_id`, `user_id` и при загрузке восстанавливаются в ссылки на объекты.

## Назначение модулей

### `boardgames/`
Пакет настроек Django-проекта: `settings.py` — настройки (приложения, язык `ru-RU`, часовой пояс
`Europe/Moscow`), `urls.py` — маршрутизация верхнего уровня и `handler404`, `asgi.py`/`wsgi.py` — точки
взаимодействия с сервером.

### `homepage/`
Главная страница: view-функции `index()` и `page_not_found()`, шаблоны `index.html` и `404.html`,
а также общие static-файлы проекта (CSS, JavaScript, логотип).

### `catalog/`
Раздел игр: view-функции `games()` и `game_detail()`, маршруты подключены с префиксом `games/`.
Приложение названо `catalog`, а не `games`, чтобы не конфликтовать с модулем `games.py` из ПР3.

### `ratings/`
Раздел отзывов: view-функции `reviews()` и `review_detail()`, маршруты подключены с префиксом `reviews/`.
Название `ratings` выбрано, чтобы не конфликтовать с модулем `reviews.py` из ПР3 (и совпадает с `data/ratings.json`).

### Пользователи
Отдельное Django-приложение для пользователей не создаётся: Django предоставляет встроенную модель
`User` (`django.contrib.auth`). Класс `User` из ПР3 используется для отображения автора отзыва.

## Текущее состояние и план развития

Реализовано (ПР5):
- Django-проект `boardgames` и три Django-приложения (`homepage`, `catalog`, `ratings`);
- маршрутизация URL двух уровней с динамическими адресами `<int:...>`;
- view-функции и страницы, навигация между ними;
- отображение данных предметной области ПР3 (игры, категории, отзывы, пользователи);
- обработка несуществующих объектов (код 404) и собственная страница 404;
- оформление Bootstrap 5.3.

Реализовано (ПР6):
- перевод всех страниц на шаблоны Django и удаление функции `page()`;
- базовый шаблон `base.html`, наследование `{% extends %}` и блоки `{% block %}`;
- включаемые шаблоны `{% include %}` (навигация, карточка игры, отзыв, бейдж оценки);
- передача данных через контекст, циклы `{% for %}`/`{% empty %}` и условия `{% if %}`;
- пространства имён `app_name` и ссылки `{% url %}`;
- фильтры шаблонов;
- собственные static-файлы: CSS, JavaScript, изображение.

Данные по-прежнему хранятся в JSON; Django ORM, база данных и формы пока не используются.

Планируется:
- перенос сущностей `Category`, `Game`, `User`, `Review` в Django ORM и подключение базы данных;
- формы добавления отзывов и игр, поиск и фильтрация в веб-интерфейсе;
- регистрация пользователей;
- разработка API, контейнеризация, CI/CD.
